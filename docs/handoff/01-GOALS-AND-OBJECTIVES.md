# Goals and Objectives

## Primary goal
Make editing a WordPress post simple and reliable on phone, tablet and desktop, with Post Content and Post Metadata always reachable and editable.

## Objectives
1. **Native editability first:** never cover WordPress Post Content or metadata with a 9CODE layer.
2. **Space efficiency:** keep Save/Update/Publish visible; move nonessential 9CODE/plugin toolbar actions into a hamburger.
3. **No full-screen editor chrome:** the hamburger must be a compact non-modal popover, not a drawer/backdrop/shell occupying the viewport.
4. **Data Manager completeness:** 9 Data Post Editor must have explicit Post Content and Post Metadata tabs.
5. **Normal post-screen recovery:** normal WordPress post edit screens must include a 9 Data recovery path exposing the same real content and metadata.
6. **Provider ownership:** ACF, Rank Math, Elementor and other plugins keep ownership of their fields and save callbacks.
7. **Safe metadata handling:** ordinary custom meta can be edited directly; private/system/provider-owned meta is visible for diagnosis but protected from unsafe raw overwrite.
8. **Mobile-first:** 320-430px widths must remain usable without horizontal editor obstruction.
9. **Regression guardrail:** Theme/Core/Data entry points, data contracts and existing conference/provider compatibility must remain intact.
10. **Portable continuation:** another AI/Codex must be able to continue from this package without reconstructing the history from chat.
