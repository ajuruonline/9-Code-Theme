# 9Code ACF Data Engine

## v0.14.0 — Change Review Dashboard

Before an AI, Excel or CSV import is applied, the preview now produces a mobile-first **Before → After** review instead of only a total count. It shows affected records, actual value changes, ACF changes, taxonomy changes, protected conflicts and errors, then lets the user expand individual changes by record and field.

The review is generated by the same import comparison logic that performs the write, so it respects Scope Lock, three-way Excel conflict protection and the data-only firewall. Applied imports also retain the exact change summary for the result screen. Large reviews are capped to 250 displayed rows while retaining the full totals.

No post publishing controls or Gutenberg editing were added.

## v0.8.0 — Universal Data Workspace

The Data Engine now treats safe WordPress post meta from **9 plugins and other plugins** as first-class editable data alongside ACF and taxonomies.

The everyday workflow stays simple:

> Choose a post type → sort/find a record → Edit Data → change ACF fields, plugin fields or taxonomies → Save.

Key changes:

- discovers safe custom/plugin post meta regardless of which plugin created it;
- excludes duplicate raw ACF storage keys and protects WordPress/Elementor design internals;
- includes registered meta fields even when they are currently empty, so they can be populated quickly;
- shows plugin fields in a separate collapsed section in the single-record editor;
- Edit Many can select plugin fields and populate a field across records even when that field was empty on a particular row;
- plugin meta participates in Excel/XLSX, CSV and AI/JSON export/import;
- Excel plugin fields use the existing hidden Map sheet and very-hidden Original sheet, so three-way conflict protection also applies to plugin meta;
- plugin meta participates in automatic Versions, import rollback and Undo through the same data-only safety layer;
- record browsing adds familiar WordPress sorting and direct Import Data access;
- secondary plugin/taxonomy sections and Edit Many rows stay collapsed by default for a cleaner mobile workspace;
- Excel remains the safest round-trip format; CSV is the quick interchange format; AI/JSON is the structured AI format.

The data-only firewall remains unchanged: no post title, slug, status, author, publishing or Gutenberg editing is introduced.


## v0.7.0 — Atomic bulk import safety

Applied Excel, CSV and AI/JSON imports now use a two-phase safety path:

- the entire import is validated before any ACF/taxonomy write begins;
- existing data versions are captured before the applied bulk change;
- every ACF value, taxonomy-item edit, taxonomy assignment and newly created taxonomy item is tracked as part of the current import batch;
- if a WordPress/ACF write fails during the applied import, the plugin automatically restores every earlier change made by that same import;
- taxonomy items created by the failed import are removed during rollback, after their assignments are restored;
- failed atomic imports are not added to Undo history as if they had succeeded;
- the report clearly distinguishes a validation-blocked import, a committed import and an automatically rolled-back import.

The data-only firewall remains unchanged: this engine still never creates or edits post publishing identity.

## v0.6.0 — Data-only firewall

9Code ACF Data Engine now enforces a hard architectural boundary with 9 Post Manager:

- it **never creates WordPress post records** during Excel, AI or backup restore;
- it **never changes post title, slug, status or parent** during any import/restore path;
- missing records are reported clearly and must be created/restored in 9 Post Manager first;
- taxonomy terms/items may still be created and restored because taxonomy data belongs to this engine;
- ACF values, taxonomy assignments, versions, rollback snapshots, allocations, field-group data and supported media references remain in scope;
- legacy v0.5 `identity_post` undo entries are safely skipped instead of mutating post publishing identity.

This closes a v0.5 backup-restore loophole where a Data Pack could create records or restore publishing identity even though the normal import screen promised data-only behaviour.


Version 0.5.0

## What this plugin is

**9Code ACF Data Engine is the data-management system for the 9Code / 9 plugin ecosystem.**

It is not a post editor.

- **9 Post Manager** manages the post itself: title, status, publishing, author and other post controls.
- **9Code ACF Data Engine** manages the data inside the record: ACF values, headings, paragraphs, images, repeaters, categories, tags and custom taxonomies.

The normal working rule is simple:

> Find the record → edit its data → Save Data.

The saved value goes back into the real ACF field. Elementor templates, shortcodes, front-end templates and 9 plugins that read that ACF field immediately receive the new value.

## What counts as data

Anything stored in ACF counts as data here, including:

- headings and short text
- paragraphs and long text
- WYSIWYG / rich text
- numbers
- dates and times
- links and email addresses
- images and files
- galleries
- yes/no values
- select, radio and checkbox values
- relationships and post-object values
- taxonomy fields
- repeaters
- groups
- flexible content
- other compatible ACF field types

Taxonomy assignments also count as data:

- categories
- tags
- custom taxonomy values

Taxonomy items themselves can have their visible name, description and ACF values managed here.

## What is deliberately NOT in the Data Editor

For posts, pages and custom post types, this Data Engine does not edit:

- post title
- slug
- post status
- publish/update state
- author
- parent post
- Gutenberg content
- other publishing controls

Those belong to 9 Post Manager.

The record name can appear read-only so you know which record you are working on.

## Data Editor

Open **9Code Data → Data**.

1. Choose Records or Taxonomy items.
2. Choose the data type.
3. Find the record.
4. Press **Edit Data**.
5. Change ACF values and/or taxonomy values.
6. Press **Save Data**.

Before a Data Engine ACF save, the plugin automatically records a data version for recovery.

## Data Table

Open **9Code Data → Data Table** to work across several records.

You can choose the ACF fields you want to work with and save the selection as a reusable view such as:

- Course Details
- Conference Participants
- Authors
- Products
- Lessons

Each opened row uses the real ACF field control, including WYSIWYG, image, gallery, repeater and relationship controls where ACF supplies them.

## Excel workflow

Excel is now the main human bulk-data workflow.

1. Open **9Code Data → Excel & AI** or use **Export Excel** from the Data browser.
2. Choose a data type.
3. Download the `.xlsx` workbook.
4. Open it in Excel or another compatible spreadsheet app.
5. Edit the white data cells.
6. Keep the grey record-reference cells unchanged.
7. Upload the edited workbook.
8. Press **Validate / Preview** first.
9. When the preview is correct, press **Import Data**.

### Excel workbook structure

The workbook contains:

- **Data** — the sheet you edit.
- **Help** — simple instructions and field information.
- **Map** — a hidden technical mapping sheet used to match spreadsheet columns back to ACF `field_*` keys safely.
- **Original** — a very-hidden safety baseline containing the values that existed when the workbook was exported. It is used to prevent stale Excel files from overwriting newer live WordPress data.

For ordinary values such as headings, paragraphs, dates and numbers, edit the value directly.

Complex data such as repeater, gallery, relationship and flexible-content values are represented as JSON text in Excel so their structure can be preserved.

Categories, tags and custom taxonomy values are human-readable names separated by commas.

Post title/status/publishing controls are not imported from the Excel workflow.

### Conflict protection

New Excel exports use a three-way comparison on import:

- original value at export time
- edited Excel value
- current live WordPress value

If Excel changed but the live value also changed differently after export, 9Code keeps the live value and reports a **Conflict protected** message. Unchanged Excel cells are ignored. Taxonomy conflicts are checked before missing terms are created, so rejected stale changes do not leave stray categories or tags.

Taxonomy item name/description may be updated because taxonomy data belongs to the Data Engine.

## Automatic data versions

Open **9Code Data → Versions**.

The plugin creates recovery versions before important data changes, including:

- manual ACF Data Editor saves
- taxonomy assignment saves
- taxonomy-name/description saves
- applied Excel imports
- applied JSON/CSV imports
- backup restores
- restoring an older version

Each saved version stores the record's ACF values and taxonomy assignments at that point in time.

The Versions screen lets you restore an earlier version. Before restoring it, the plugin creates another safety version of the current data.

The plugin currently keeps up to 30 versions per record and trims the global version store to a safety ceiling so the database cannot grow without limit.

The older **Undo latest import** system is also retained as a quick recovery mechanism.

## AI workflow

JSON remains available for AI round-trips.

The safe AI rule is:

- keep the record reference unchanged
- keep each ACF `field_*` key unchanged
- edit field values
- edit taxonomy values

Normal Data Engine import does not create missing posts and does not change post title, slug, status or publishing controls.

Missing categories, tags and custom taxonomy items may be created when that option is enabled.

## CSV

CSV import/export remains available for compatibility and simple data exchanges.

Excel `.xlsx` is preferred for normal human editing because it can carry friendly headings, instructions and the hidden ACF mapping sheet.

## Full portable backup

Open **9Code Data → Backups**.

The ZIP Data Pack is the broader disaster-recovery layer. It can contain:

- ACF field structure
- ACF values
- taxonomy data
- virtual field allocations
- 9Code registry definitions retained for compatibility
- referenced ACF image/file/gallery media

Use Data Versions for normal mistakes and recent changes. Use the ZIP Data Pack for full portable/off-site recovery.

## Field allocation

Use **Allocate Fields** when an ACF field group should also be available to another post type or taxonomy.

The plugin adds a virtual allocation. It does not overwrite the original ACF field-group location rules.

## Elementor

The values remain normal ACF values, so Elementor Pro can continue using its native ACF Dynamic Tags for supported field types.

The plugin also includes:

- **9Code ACF Field** Elementor dynamic tag fallback
- `[ninecode_acf]` shortcode fallback

## v0.15.0 — Verified Preview → Apply
- Uploaded AI/CSV/XLSX imports must be previewed before they can be applied.
- A successful preview secures a short-lived immutable copy of the exact uploaded file and shows an Apply reviewed changes action.
- Apply verifies the staged file SHA-256 and re-computes the complete Before → After change fingerprint before any recovery snapshot or write.
- If live data changes after Preview, Apply stops and requires a fresh Preview rather than silently applying a different change set.
- Apply tokens are one-time and expire after 30 minutes. Automatic versions, atomic rollback, Scope Lock and Excel conflict protection remain active.


## 0.16.0 — Selective Apply
Previewed AI/Excel/CSV imports can now exclude individual proposed changes before Apply. The full reviewed proposal is fingerprint-checked again before any recovery snapshot or write, and only approved change IDs can be submitted from the staged review.
